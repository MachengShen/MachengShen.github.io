Keith's Setup Guide: Claude + Grok Bot, Shared Memory over MCP, and a Travel/Hotel Email Pipeline

*Prepared by Macheng's team, 2026-10-05. Written so you can hand this file straight to your AI assistant and have it walk you through setup step by step.*

To your AI: Read the whole document before acting. Follow the steps in order. Use only the URLs listed here. If a step doesn't match what you see on screen, stop and tell Keith. Don't guess. Never send email, pay, or book anything without Keith's explicit confirmation.

---

1. Goal and boundaries

Goal. At the end of this guide Keith will have:

  • Claude (claude.ai chat and/or Claude Code), plus his own Grok Bot, signed in under his own accounts.
  • A Long-Term Memory (LTM) hub that his AI tools can read and write over MCP (Model Context Protocol), so facts and preferences carry over between sessions and devices.
  • A travel/hotel pipeline: pull hotel confirmations from Gmail, build an itinerary, and draft emails to hotels. Nothing gets sent until Keith confirms.

Out of scope (deliberately not in this package):

  • Macheng's evidence / credit system is not part of this setup.
  • No passport packs, signature packs, application files or other personal documents (PII) are included or needed.
  • No private links, internal tokens or credentials belonging to Macheng's systems. Everything below is public and open-source, and Keith runs his own copy.

2. Two tools working together: Claude + Grok Bot

2.1 Claude (you probably have this already)

  • claude.ai is the Claude chat product Keith likely already uses.
  • Claude Code (https://code.claude.com) is Anthropic's agentic coding/terminal tool. It is the simplest place to connect a custom MCP server such as the memory hub.
  • MCP documentation for Claude Code: https://code.claude.com/docs/en/mcp

2.2 Grok Bot (recommended addition)

Official pages:

  • Product page: https://x.ai/bot
  • Docs hub: https://cursor.com/docs/grok-bot
  • Get started: https://cursor.com/docs/grok-bot/get-started
  • Connect plugins (Gmail etc.): https://cursor.com/help/grok-bot/connect-plugins
  • Also referenced: https://docs.x.ai/grok-bot/

Access. Grok Bot comes with every paid individual Cursor plan and with the Cursor Teams plan. You can also get it by linking an individual SuperGrok, SuperGrok Plus or SuperGrok Heavy subscription. Check the docs for current plan details. This guide doesn't quote prices.

Sign-in. Grok Bot uses your Cursor account. There is no separate Grok Bot login. If you sign up for Cursor with Google, your Gmail-based Google account works.

Install (desktop).

  • Sign in to the Cursor dashboard with your Cursor account.
  • Open the Grok Bot page in the dashboard.
  • Use the "Download Grok Bot" setup row to install the desktop app (macOS, Windows or Linux).
  • Optional: install Grok Bot on iOS from the App Store and sign in with the same Cursor account. Your access carries over.

Note from the docs: Grok Bot needs cloud data storage. Accounts on "Privacy Mode (Legacy)" will be asked to switch to Privacy Mode before starting.

Connect Gmail (Grok Bot side).

  • In the Grok Bot app, open Plugins in the sidebar.
  • Add Gmail, then Authorize in the browser window that opens.
  • Gmail connects one mailbox at a time. To switch mailboxes, disconnect and then authorize the other one.
  • With Gmail connected, Grok Bot can search and read mail, draft and send, and apply labels. In this setup it drafts, and Keith approves each send (see §4 and §6).

If Google shows an "admin needs to review" or "access blocked" message, you are probably on a company Google Workspace account. Personal Gmail doesn't need admin approval. See the Connect plugins page above.

3. The MCP bridge: Memory Hub / Long-Term Memory

3.1 Background reading (public)

  • LTM field guide (English): https://machengshen.github.io/long-term-memory/index.en.html
  • LTM field guide (Chinese): https://machengshen.github.io/long-term-memory/
  • Architecture (design docs): https://github.com/starshard-ai/architecture-v1
  • Memory hub reference implementation (Apache-2.0): https://github.com/starshard-ai/reference-impl
  • Open-source index: https://machengshen.github.io/open-source.zh.html
  • Portal: https://machengshen.github.io/

The reference implementation is a small FastAPI + SQLite server with an MCP JSON-RPC endpoint. It provides create_memory, get_memory, update_memory, list_memories and search_memories. Keith runs his own copy and keeps his own token. Nothing is shared with Macheng's hub.

3.2 Five-minute local setup (from the reference-impl README)

Prerequisites: git, Docker (with docker compose), Python 3.


git clone https://github.com/starshard-ai/reference-impl.git

cd reference-impl



# 1. Generate a bearer token (keep it private)

python3 -c 'import secrets; print(secrets.token_urlsafe(32))' > .hub_token

cp .env.example .env

sed -i.bak "s/change-me.*/$(cat .hub_token)/" .env



# 2. Start the hub

docker compose --env-file .env up --build -d



# 3. Health check (no auth needed for this endpoint)

curl -s http://localhost:8080/healthz

# expected: {"ok":true,...}

3.3 Connect Claude Code to the hub

Option A: CLI (--transport http with a --header, as described in the Claude Code MCP docs):


claude mcp add --transport http starshard-hub http://localhost:8080/mcp \

  --header "Authorization: Bearer $(cat .hub_token)"

claude mcp list        # starshard-hub should appear

Option B: config file (the README form, ~/.claude/mcp.json):


{

  "mcpServers": {

    "starshard-hub": {

      "type": "http",

      "url": "http://localhost:8080/mcp",

      "headers": { "Authorization": "Bearer <paste contents of .hub_token>" }

    }

  }

}

Then append the repo's templates/CLAUDE.md to ~/.claude/CLAUDE.md. That file tells Claude to check memory at session start (list_memories / search_memories) and to create_memory when decisions are made, so you don't have to remind it each turn.


cat templates/CLAUDE.md >> ~/.claude/CLAUDE.md

Inside Claude Code, run /mcp to see which servers loaded.

3.4 Reaching the hub from other devices / claude.ai / Grok Bot

  • localhost:8080 only works on the machine running the hub. claude.ai on the web and Grok Bot's cloud computer cannot reach your laptop's localhost.
  • To use one hub from several devices, follow the reference-impl's AWS option and its INSTALL.md (Cloudflare Tunnel + Access, the production-grade variant). Do that before you store real data in it.
  • Grok Bot: for current support for custom MCP servers and rules, check the Grok Bot docs (https://cursor.com/docs/grok-bot). Until you've confirmed a supported path, let Grok Bot handle Gmail through its plugin and keep Claude Code as the hub client. Have Claude store the itinerary summary and your travel preferences in the hub.

4. Recommended travel/hotel pipeline

Shape: Gmail → hotel confirmations → itinerary → draft hotel emails → Keith confirms → send.

| Step | Who | What | |---|---|---| | 1. Pull | Grok Bot (Gmail plugin) | Search the mailbox for hotel confirmations, e.g. subject:(confirmation OR reservation OR booking) (hotel OR resort) within a date window. | | 2. Extract | Grok Bot | For each booking: hotel, city, check-in/out dates, confirmation number, cancellation deadline, contact email. | | 3. Itinerary | Grok Bot | One table in date order. Flag gaps (nights with no booking), overlaps (two hotels on one night) and cancellation deadlines in the next 7 days. | | 4. Remember | Claude Code + hub (optional) | create_memory with tag travel: trip summary and stable preferences (room type, late check-in habits, loyalty programs by name only, no numbers). | | 5. Draft | Grok Bot | Draft emails to hotels (early check-in, late checkout, airport transfer, reconfirmation). Drafts only. | | 6. Confirm | Keith | Review each draft card, edit if needed, approve. Only then is it sent. |

Never automatic: sending mail, paying, booking, cancelling, or accepting new terms/prices. All of these need Keith to say yes.

4.1 Copy-paste prompt for Keith's AI (setup + first run)


You are helping me (Keith) set up and run a travel/hotel assistant.

Read the attached guide "Keith's Setup Guide" fully first.



Setup:

1. Walk me through Section 2 (Claude + Grok Bot sign-in, Gmail plugin) one step at a time.

   Wait for me to confirm each step before moving on.

2. Walk me through Section 3 (reference-impl memory hub, Claude Code MCP wiring).

   Use only the commands in the guide. If anything errors, show me the exact

   error and propose one fix at a time.

3. Run the Acceptance Checklist in Section 5 and report pass/fail per item.



First run (after setup):

4. Search my Gmail for hotel confirmations for trips in the next 90 days.

5. Build one itinerary table in date order: hotel, city, check-in, check-out,

   confirmation #, cancellation deadline, hotel contact. Flag gaps, overlaps,

   and deadlines within 7 days.

6. Propose any useful hotel emails (e.g. late arrival, early check-in) as DRAFTS.

   Do NOT send anything. Show me each draft and wait for my explicit "send".



Rules: never pay, book, cancel, or send on my behalf without my explicit OK.

Never paste passwords, tokens, card numbers or passport details into chats or memory.

Lead with results (the table, the drafts, or the blocker), not step-by-step narration.

4.2 Sample Grok Bot standing instruction (travel email drafting)

Paste this into your Grok Bot as a standing instruction / rule:


TRAVEL EMAIL STANDING INSTRUCTION

- When I mention a trip or hotel, search my connected Gmail for the matching

  confirmation(s) first. Don't ask me for details that are already in my mail.

- Keep a current itinerary table (date order). Flag gaps, overlaps, and

  cancellation deadlines inside 7 days.

- Hotel emails: write a DRAFT only. Keep it short and polite, include the

  confirmation number and guest name, and state one clear request.

  Show me the draft card and wait for my approval before anything is sent.

- Never send, pay, book, cancel, upgrade, or accept a price change on my behalf

  without my explicit "yes, send" / "yes, book".

- Never include card numbers, passport numbers, or passwords in any email or note.

- Report results first: the table, the drafts waiting for approval, or what's blocked.

6. Public standing checklist (recommended rules for your AI)

These are the house rules Macheng's assistants follow. They contain no private data, so you can paste them into your own AI's instructions.

  • Result-only surface. Lead with the usable artifact, the blocker, or a go/no-go. Skip tool-by-tool narration.
  • External send = draft first. A human confirms before anything is sent (Grok Bot draft card / approval). Never auto-send money, commitments or mail as the owner.
  • Speech-to-text. Quietly correct obvious homophones from context. When the intent is clear, don't act on the literally wrong transcription.
  • Memory before asking. Search the hub / memory (e.g. reference-impl search_memories) before asking the human again for facts already stored.
  • Phone-first links. Only give the human a URL after it has returned HTTP 200. Prefer one clean link over attachments or file paths.
  • Irreversible actions (pay, book, delete, committing other people): stop and ask the human.

8. Agent-to-agent communication (so your AI can ask Macheng's AI for help)

8.1 What problem it solves

When something breaks during setup, it helps if Keith's AI can talk directly to Macheng's AI instead of relaying screenshots back and forth. Starshard Communication is an open protocol for this. It gives agents an interoperable inbox and addressing, identity and trust (who is talking), and receipts (proof a message was delivered and read). The optional Fleet Coordination Protocol (FCP) is a narrow wire format for multi-agent coordination, for when several agents need to divide work.

8.2 Where to start (public materials only)

  • Overview page: https://machengshen.github.io/agent-comm-protocol.html
  • Starshard Communication docs site: https://starshard-ai.github.io/starshard-communication/
  • SPEC-0003 (agent identity, authentication and secure messaging): https://starshard-ai.github.io/starshard-communication/docs/SPEC-0003-agent-identity-authentication-and-secure-messaging
  • GitHub (spec + code): https://github.com/starshard-ai/starshard-communication
  • Fleet Coordination Protocol (optional): https://github.com/starshard-ai/fleet-coordination-protocol

High-level setup:

  • Have your AI read the overview page, then SPEC-0003.
  • Follow the setup instructions in the starshard-communication repository to give your agent an identity and an inbox.
  • Exchange agent addresses with Macheng through a normal human channel. This guide doesn't publish any private endpoint, so ask Macheng directly for his agent's address when you're ready.
  • Add FCP only if you later run several agents that need to coordinate.

8.3 Hard boundaries

  • Keith's AI may consult Macheng's AI for technical help (setup, errors, configuration).
  • It must not make commitments, payments or legal promises in Macheng's name (or in Keith's) on its own initiative.
  • No secrets or PII across the link (tokens, passwords, card or passport numbers, private documents) unless a human on each side explicitly approves.
  • Anything irreversible that comes out of an agent-to-agent conversation goes back to the humans for a yes/no.
