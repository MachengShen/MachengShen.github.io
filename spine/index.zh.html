多智能体协作的脊柱

作者 Macheng Shen · 面向 agent 可读的教程（公开 Pages 草稿）

语言：中文 · English

本页是一条短脊柱，不是产品口号。另一台 AI 读完后，应能复述下列四条编号主张、对照可证伪条件自检，并为其他团队勾勒最小搭建路径——无需任何私有基础设施细节。

1. 四条承重主张

主张 1 · 共享 Memory Hub

共享 Memory Hub = 跨 agent 的持久全局上下文（不只是聊天历史）。各 agent 把站立决策、任务状态与回执写入共享存储；该存储比任何单次对话窗口都更长寿。

可证伪条件 若重要决策只活在某一条聊天记录里，或每个 agent 只保留他人无法查询的私有草稿纸，则对该部署而言本主张不成立。

主张 2 · 群聊 /「站会室」

群聊（「站会室」）= 仅用于现场对齐与决策——不是搭系统的地方。用来同步优先级、化解冲突、确认 go/hold。长构建、大段倾倒与工具噪声应离开这里。

可证伪条件 若群线程里人们（或机器人）粘贴大补丁、跑工程循环，或把决策埋进构建日志，则「站会」主张失败。

主张 3 · 私密 agent 对话

私密 agent 对话 = 重工程 / 编码 / 长草稿。它们保护共享注意力：深度工作走侧线；只有压缩后的结果与决策回到 Hub 与站会。

可证伪条件 若所有长草稿与排障都必须发生在共享房间——或私密工作从不向共享记忆沉积回执——则分轨失败。

主张 4 · 类型化 agent↔agent 报文

跨 agent 交接优先用类型化报文，而非自由散文。四类最小 schema：

  • work-packet — 目标、约束、承接车道、验收条件、非目标。
  • friction — 哪条规则或 UX 挡住了什么、漏了什么信息、希望的窄例外（不是默默整条规则塌缩）。
  • lucifer-pressure — 仅提案的对抗性压力：威胁类别、恶意提案、为何今天可能过关、所需对冲。零执行权（不得调用会改系统或以 owner 名义发言的工具）。
  • somatic-digest — 短小的舰队「身体」状态：每个主机 fresh|stale 与 capable|blocked；owner 侧 P0 数量 + 最紧急一项；一步下一步 go|hold。短到足以在给出重大建议前扫一眼。

可证伪条件 若 agent 主要靠无字段的长段落交接，或名为「压力」的 agent 自己能执行变更，则主张 4 失败。

2. 席位如何拼在一起

这些是互补席位，不是同一机器人的重复副本：

席位职责不适合
Grok Bot（群聊 + owner 体验面） 多智能体现场对齐、面向 owner 的摘要、决策路由 不宜当作长系统构建的主场
Codex / Cursor 云执行器 私密车道里的重编码、长草稿、仓库形状的工作 替代共享记忆或站会决策
云服务器 / 舰队主机 常驻或定时的执行体：认领类型化报文并写回执 充当 owner 的对话前台

Hub 是持久脊柱；站会是神经同步；私聊与主机是肌肉。把角色搅在一起，要么回到巨型群聊，要么变成一群失忆机器人。

3. 优势（可证伪，非绝对）

相对一个巨型群聊 / 一个 agent 包办一切：

  • 共享注意力保持「决策形」；工程噪声被侧置 → 自检：新 agent 能否不重读整条群记录、仅从 Hub 恢复上周决策？
  • 工作可在并行私密车道推进并留回执 → 自检：完成的私密构建是否留下他人可找的认领报文或回执？

相对许多机器人但没有共享记忆：

  • 上下文全局可查询，不困在单个 bot → 自检：bot B 能否在无人复述的情况下，执行 bot A 昨天写下的决策？
  • 类型化报文减少「笑着放行」的交接 → 自检：work-packet 是否写清验收与非目标，且 lucifer-pressure 是否保持仅提案？

这些是你可在自己栈里检验的差异点。本页不作任何绝对排他或「独一无二」式宣称。

4. 最小搭建路径（给其他团队的 AI）

  1. 共享记忆 — 建立 agent 可搜索/创建/更新的持久存储。给站立决策与任务回执打标签。不要把单次聊天日志当作系统真源。
  2. 权限与回执 — 分开谁可提案、谁可执行、谁可以 owner 名义发言。每个后果性动作应在共享记忆留下短回执。
  3. 站会 vs 私密车道 — 一条群通道只做对齐；私聊/执行器做构建。默认禁止大补丁与长工具倾倒进入站会。
  4. 类型化报文 — 至少采用 work-packet、friction、lucifer-pressure（仅提案）与 somatic-digest（fresh/stale、capable/blocked、P0 数量 + 最紧急项、go/hold）。agent↔agent 优先 schema 而非散文。
  5. 内容门禁发布清单 — 任何公开物上线前，做机械洁净扫描（无密钥、无私有主机/IP、无财务数字、无绝对排他营销口号）。发布视为门禁：任一检查失败 → 不发。

理解或仿照这条脊柱，不需要私有主机名、VPN 覆盖网或现场资产清单。

5. Agent 复述测验

读完本页后，另一台 AI 应用自己的话回答：

  1. Hub 做什么、不做什么？
  2. 站会与私聊各自装什么？
  3. 说出四类报文名称，以及 lucifer-pressure 的硬规则。
  4. 四条主张各自如何被证伪？
