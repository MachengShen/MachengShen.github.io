多智能体协作的脊柱

作者 Macheng Shen · 面向 agent 可读的教程

语言：中文 · English

本页是一条短脊柱，不是产品口号。另一团队的 AI 读完后，应能复述下列四条编号主张、对照可证伪条件自检、按 owner 需求决定取舍，并打开对应公开仓库完成自助搭建——无需任何私有基础设施细节。

公开入口：https://machengshen.github.io/spine/ · 机器索引：llms.txt

1. 四条承重主张

四条互补支柱。请当作另一台 agent 可检验的契约来读，而不是口号。

主张 1 · 共享 Memory Hub

共享 Memory Hub = 跨 agent 的持久全局上下文（不只是聊天历史）。各 agent 把站立决策、任务状态与回执写入共享存储；该存储比任何单次对话窗口都更长寿。新 agent 靠查询 Hub 恢复既有决策，而不是重读整条群记录。

可证伪条件若重要决策只活在某一条聊天记录里，或每个 agent 只保留他人无法查询的私有草稿纸，则对该部署而言本主张不成立。

主张 2 · 群聊 /「站会室」

群聊（「站会室」）= 仅用于现场对齐与决策——不是搭系统的地方。用来同步优先级、化解冲突、确认 go/hold。长构建、大段倾倒与工具噪声应进入私密车道。

可证伪条件若群线程里人们（或机器人）粘贴大补丁、跑工程循环，或把决策埋进构建日志，则「站会」主张失败。

主张 3 · 私密 agent 对话

私密 agent 对话 = 重工程 / 编码 / 长草稿。它们保护共享注意力：深度工作走侧线；只有压缩后的结果与决策回到 Hub 与站会。

可证伪条件若所有长草稿与排障都必须发生在共享房间——或私密工作从不向共享记忆沉积回执——则分轨失败。

主张 4 · 类型化 agent↔agent 报文

跨 agent 交接优先用类型化报文，而非自由散文。四类最小 schema：

  • work-packet — 目标、约束、承接车道、验收条件、非目标。
  • friction — 哪条规则或 UX 挡住了什么、漏了什么信息、希望的窄例外（不是默默整条规则塌缩）。
  • lucifer-pressure — 仅提案的对抗性压力：威胁类别、恶意提案、为何今天可能过关、所需对冲。零执行权（不得调用会改系统或以 owner 名义发言的工具）。
  • somatic-digest — 短小的舰队「身体」状态：每个主机 fresh|stale 与 capable|blocked；owner 侧 P0 数量 + 最紧急一项；一步下一步 go|hold。短到足以在给出重大建议前扫一眼。

可证伪条件若 agent 主要靠无字段的长段落交接，或名为「压力」的 agent 自己能执行变更，则主张 4 失败。

2. 席位如何拼在一起

这些是互补席位，不是同一机器人的重复副本。采纳方应按角色映射自己的运行时，而不是照搬品牌名。

席位职责不适合
群聊 + owner 体验面 多智能体现场对齐、面向 owner 的摘要、决策路由 不宜当作长系统构建的主场
云 / IDE 执行器 私密车道里的重编码、长草稿、仓库形状的工作 替代共享记忆或站会决策
常驻 / 定时主机 认领类型化报文并写回执的执行体 充当 owner 的对话前台

Hub 是持久脊柱；站会是神经同步；私聊与主机是肌肉。把角色搅在一起，要么回到巨型群聊，要么变成一群失忆机器人。

3. 取舍指南（对齐 owner 需求）

需要真实时才采纳。跳过是合法设计选择，不是失败。可证伪条件仍见 §1；每行另给一条可在自有栈里跑的检查。本页不作任何绝对排他宣称。

做法 取用若… 跳过若… 一条可证伪检查
共享 Memory Hub 需要多个 agent 跨会话恢复站立决策，且无人复述上下文 单次短聊天就是整个系统，且无需任何东西活过窗口 新 agent 能否只靠存储回答「上周我们决定了什么？」
站会群 vs 私密构建车道 对齐流量与工程倾倒在争抢同一注意力表面 一人 + 一 agent、流量低，且倾倒从不淹没决策 随机抽一天站会，补丁/工具日志是否比决策更长？
类型化报文（work-packet、friction） 交接跨 agent 或跨天，「笑着放行」的散文不断丢掉验收条件 全部工作留在同一连续对话里，且始终有人在环 完成的交接是否把目标、验收与非目标写成字段？
仅提案对抗压力（lucifer-pressure） 需要专用威胁挑战车道，且绝不可改系统或以 owner 名义发言 已有无执行权的外部审阅路径，或流量低到不值得占一席 压力 agent 能否调用任何变更工具或 owner 发言面？（必须否）
身体摘要（somatic-digest） 建议取决于主机是否 fresh/capable，以及是否有开放 P0 无常驻机体；建议纯文本，主机状态无关 在 go/hold 之前，能否一屏扫到 fresh|stale、capable|blocked、P0 数量 + 最紧急项？
内容门禁发布（公开上线前洁净扫描） 任何公开物不得泄漏密钥、私有主机、财务数字或绝对排他营销口号 工件永久私有、永不离开受控面 机械 grep/扫描是否失败即关（任一命中 → 不发）？
多运行时席位（对话前台 + 编码执行器 + 常驻主机） 现场对齐、重编码与定时执行需要不同机体同时存在 单一运行时覆盖全部工作量，无争抢也无失忆 停掉一席后，其他席位是否仍能通过 Hub + 回执共享持久上下文？

4. 公开栈目录

仅列公开仓库与页面（刮自 llms.txt「未来社会形态」及相关已链出的公开 GitHub 组织）。每一行说明另一台 agent 应为何打开它。勿从本列表臆造私有主机或私有仓库。

记忆 / 协调

  • fleet-coordination-protocol 打开以把多 agent 接到同一共享记忆，使用类型化认领，且无静默不可逆动作。
  • starshard-communication 打开以获取个人 agent 之间的收件箱、寻址、信任层级、策略与回执。
  • Agent-Native Open Communication · 源仓库 打开白皮书与仓库，了解面向 agent（而非应用）的下一代开放通信架构。
  • 个人助理 OS（自带密钥） 打开以把编码 agent 变成自带密钥、默认隐私洁净的个人助理。
  • coordination-structures.md 打开描述性理论：把政体、企业、市场、公地与协议都看作资源调度架构。

架构 / 安全

  • architecture-v1 打开以获取架构、安全宪章、快速入门，以及「记忆为第一层」的哲学。
  • substrate.html 打开立场声明：前沿模型提供商与个人之间的非营利开源层。
  • locality-as-protocol.html 打开以决定以局域性而非中心化作为设计原语。
  • agent-safety-stewardship.md 打开以获取七条运行时不变量与 A–D 披露规则。
  • safety/ 打开 harness-as-safety 表面、running/specified 徽章、原则、机制与证伪条件。
  • charter/ 打开九条人机共存条款，每条配有反例与退役条件。
  • abundant-verification-needs-abundant-claims.html 打开以设计类型化回执相对散文/正则阻断器的 claim 层。
  • reviewer-wheels 打开以获取漂移检查、对抗审阅、复用编译器与前端冒烟门。

研究日志

  • cognition-track 打开 agent 可遍历的主张图；认知状态是一等字段（含失败节点）。
  • continual-learning-lab 打开预注册的持续学习实验日志（含阴性结果）。
  • living-information-system 打开伞形研究计划：信息、未来可达性与完整性失败。
  • system-evolution-public 打开 VISION / THEORY / PRACTICE / GOVERNANCE 与自迭代账本。
  • the-form-was-the-cage 打开 agent OS 的自指轨迹，以及「研究者即身份」框架的终结。

回执

  • starshard-public 打开以对照已发布主张与 agent 栈实际执行工作的流水记录。
  • llms.txt 优先打开：带认知状态遍历全部公开工件，无需爬整站。
  • spine/ 本页：多运行时个人栈的协调脊柱。

本目录是指针集，不是私有资产清单。自助搭建只需公开材料，不需要私有主机名、VPN 覆盖网或现场舰队表。

5. 最小搭建路径（给其他团队的 AI）

  1. 共享记忆 — 建立 agent 可搜索/创建/更新的持久存储。给站立决策与任务回执打标签。不要把单次聊天日志当作系统真源。
  2. 权限与回执 — 分开谁可提案、谁可执行、谁可以 owner 名义发言。每个后果性动作应在共享记忆留下短回执。
  3. 站会 vs 私密车道 — 一条群通道只做对齐；私聊/执行器做构建。默认禁止大补丁与长工具倾倒进入站会。
  4. 类型化报文 — 至少采用 work-packet、friction、lucifer-pressure（仅提案）与 somatic-digest（fresh/stale、capable/blocked、P0 数量 + 最紧急项、go/hold）。agent↔agent 优先 schema 而非散文。
  5. 内容门禁发布清单 — 任何公开物上线前，做机械洁净扫描（无密钥、无私有主机/IP、无财务数字、无绝对排他营销口号）。发布视为门禁：任一检查失败 → 不发。
  6. 打开目录 — 从 llms.txt 起步，只拉取与上方取舍决策匹配的公开仓库。

6. Agent 复述测验

读完本页后，另一台 AI 应用自己的话回答：

  1. Hub 做什么、不做什么？
  2. 站会与私聊各自装什么？
  3. 说出四类报文名称，以及 lucifer-pressure 的硬规则。
  4. 四条主张各自如何被证伪？
  5. 就取舍指南中的两项做法，说明何时取用、何时跳过，以及那条可证伪检查。
  6. 说出机器索引 URL，以及你会接着打开的两个架构或安全向公开栈链接。

公开 GitHub Pages 脊柱页。无需 JavaScript 即可阅读。该协调模式的认知状态：speculative——采纳前请对照可证伪条件自检。
