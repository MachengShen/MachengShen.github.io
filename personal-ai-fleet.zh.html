一个人的 AI 小队：在 Signal 里直接跟它说话

为什么要这样搭？AI 厂商很多，新 App 还在不断出现；一旦把工作和历史托付给某一家，离开就会很贵。这套系统刻意不黏人：模型和平台都是可替换的零件，而真正沉淀价值的部分——记忆、聊天、邮件、规则和回执——放在开放、自己拥有的组件里。出了更好的模型，直接换上，什么都不丢。

给不写代码的人看的说明。下面写的都是真实在跑的东西；还没做的明确标成“计划中”或“已设计”。

已实现 已经做出且可用（不一定达到生产稳定）　部分 / 已设计 能用但有缺口，或已有规范但尚未完整实现　计划中 还没有

不用装新 App：在常用的聊天软件里（这里用 Signal）给助手“Sophon”发消息即可。可替换的小队负责研究、执行和检查；凡是要替你对外说话或花钱，都只先给草稿，得到批准才会发出。

1. 入口与通信

它为主脊柱解决的问题：如果对话和交付路径都属于某一个 App，换 App 时就会丢掉关系、历史记录，或者两者一起丢。

Signal 可以通过“已连接设备”成为日常入口；自托管网页聊天把每个联系人的记录保存成你磁盘上的 JSONL 文件；邮件提供本地持久队列、附件接收和“邮件唤醒 agent”。如果 SMTP 投递失败，邮件正文会留在本机，不会回退到云端服务。带令牌保护的网页还能让手机操控自己机器上的 agent，fleet-drop 则能把另一台机器上的文件送到手机 Signal。通信规范进一步定义了用户拥有的收件箱、地址、信任等级、生命周期回执，以及不绑定供应商的 agent 身份与委托权限设计。

已实现 signal-agent-pipeline、selfhost-chat、agent-mail-stack · 已设计 / 部分实现 starshard-communication

2. 调度与可替换席位

它为主脊柱解决的问题：即使数据能搬走，流程若依赖某个模型的性格或工具，仍然是一种锁定。

小队绑定的是席位，不是固定模型名：你发消息的聊天入口把请求交给调度；调度分派带验收检查的工作包；建造者执行；新的验证者重新运行这些检查；独立评审从另一类约束找问题。任何席位都能换模型、机器或平台。协作 work claim 能减少跨会话重复开工；它是租约，不是授权机制，也不保证“恰好执行一次”。

已实现，v0 实验性 fleet-coordination-protocol 中的跨会话事实、work claim、回执和冲突隔离 · 可运行子集 agent-continuity-demo

3. 一份用户拥有的共享记忆

它为主脊柱解决的问题：只有当决策、偏好、任务状态和回执能活过每次会话，换 agent 才真正没有损失。

所有席位都能通过 HTTP 或 MCP 使用同一个可搜索的记忆库。参考服务把数据存在你控制的基础设施和 SQLite 里。夜间 Mirror 提出合并建议；假设检查器发现逻辑冲突；每周摘要用邮件呈现系统学到了什么，让改进可见；连续性演示则把相互矛盾的新信念放入隔离区，而不是静默覆盖已有事实。聊天记录和邮件仍是独立的开放档案，不被困在某个模型的内置记忆中。

边界要说清楚。参考服务尚未强制校验 provenance 字段，也没有实现架构文档里的若干更强安全控制。它是 Phase 0 的底座，不是完整安全边界。

已实现 reference-impl · 架构与安全契约：architecture-v1

4. 硬规则与批准

它为主脊柱解决的问题：可替换的模型需要稳定、位于提示词之外的权限边界，否则每次换模型都可能改变系统能做什么。

  • 有后果的动作先出草稿。对外发送、公开发布和花钱必须等人批准；超时永远不等于批准。
  • 不可逆动作前先写回执。通信设计采用“意图回执 + 执行回执”：动作前可核对授权，动作后记录结果。这个更强的两阶段协议是已设计，不是 FCP v0 已保证的能力。
  • 内容也是权限边界。公开材料必须通过失败即关闭的机械洁净扫描；即使执行者有发布工具，内容不合格也不能发布。
  • 信任与权限只减不增。发现工具不等于把它暴露给系统；密钥不进共享记忆，抢占、继承和只能收窄的权限信封都不能扩大权限。身份与权限规范目前是已设计。
  • 花费有两道墙。公开自托管聊天在模型调用前检查本地每日预算，并建议再设置上游账户级限额。

5. 验证与可观测性

它为主脊柱解决的问题：数据可搬还不够；替换后的 agent 必须能判断事情是否真的发生、通道是否真的可用、结果从哪里来。

完成回执可以记录产物、SHA-256 指纹、规则版本，以及由干净上下文或另一台机器复查的证据。在分层架构说明描述的运行试验中，只看证据的 Gate 有四种判定；只有非建造者主机重新检查后给出的 verified-mechanical 才能称为“已验证”。试验还会用预埋故障盲测验证者；漏掉一个关键故障就撤销其放行权，必要时可用 kill switch 停用该席位。

通道健康要靠端到端探测：“进程在跑”只是心跳，“确实收到了”才是健康。对 Signal 而言，发送证明是服务器返回 SUCCESS，不是发送进程的退出码。SPEC-0002 用漏报监控、被过滤消息摘要、不确定性升级、重复发送检测和可运行演示，发现被静默过滤的重要消息。验证技能包括漂移镜像、按约束分工的对抗评审、复用检查、前端冒烟门、委派边界和仓库分诊；技能 provenance 则记录制作者、来源、版本、许可和问题入口，不夹带营销话术。

技能已提供 reviewer-wheels（六项） · skill-provenance · 并非所有回执都经过独立验证，各仓库会说明自己的证明边界。

6. 开放组件与仓库

它为主脊柱解决的问题：一套不能用零件重新搭起的系统，并不真正属于你。

可以只拿一条分支，也可以逐步组合；不必把整条数据流交给一家厂商。许可为 MIT / Apache 混合；通信白皮书为 CC-BY-SA-4.0。

从小处开始。先运行记忆库，接一个通信入口，并强制“发送或花钱前先给草稿”。只有当多个 agent 真正造成协调问题时，再加协调与验证。公开托管、加好友即可使用的 bot 和一体化安装包都仍是计划中，今天还不可用。

这些是从真实系统中抽出的实验组件，会有 bug；在让它们接触重要数据或动作前，请先读各仓库写明的边界。
