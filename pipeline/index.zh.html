给人看 · 流水线上的一天

你不必自己跑智能体也能读懂。把它想成七个站点的协作模式。每个站点对应真实工作日里反复出现的摩擦（2026-09-16 公开安全改写）。

站点 1 · 多智能体群聊当站会

早晨从共享房间开始：多个智能体 + 主人。房间职责是只对齐：优先级、go/hold、谁负责哪条车道。长补丁、工具倾倒、调试循环不属于这里——它们会淹没决策。

可检验：若随机一天的共享线程大半是构建噪音，站会主张就失败了。

站点 2 · 共享 Memory Hub 承载长期偏好

聊天会过期。必须跨会话存活的偏好写入 Shared Memory Hub：可检索的 standing 决策、任务回执、其他智能体可读的共享画像。

主人话术模式：有人说「记下了」，意图应是三连写入——不是礼貌口头回应：

  1. 写一条 Hub standing（持久、可搜）。
  2. 更新其他座位会读的共享画像 / session-prime。
  3. 通知兄弟智能体，避免大家重新「发现」同一偏好。

若 1–3 步没发生，「记下了」就是失败模式——哪怕聊天看起来很客气。

站点 3 · 核心产品 harness 关闭时的外层壳

有些日子主产品 harness（常用 IDE / 云端编码面）不可用、限流或卡在鉴权。流水线仍需要能起草、暂存文件、跑机械检查的地方。

这里的外层壳（outer harness）指二级运行时或草稿工作区：核心 harness 重开前先把活接着干。它是连续性模式，不是第二真相源：standing 决策仍进 Hub。

站点 4 · 公开 spine 页讲架构

有人问「栈长什么样？」时，不要在 Slack 里再写长文。指向公开架构页：

https://machengshen.github.io/spine/

那一页讲共享记忆、站会 vs 私聊车道、类型化数据包，以及带可证伪条件的取用/跳过指南。本页是「一日流水线」；spine 是地图。

站点 5 · Slack + Cursor Cloud Agents 需要仓库

挂在 Slack 上的云端编码智能体是仓库形态的，不是漂浮的 REPL 窗口。让它开工前先选仓库——最好有专用的默认草稿仓库，避免污染产品仓或 Pages 仓。

硬坑。个人账号登录 Cursor ≠ 在 GitHub组织上安装 Cursor GitHub App。没有组织级 App 时，即使仓库 URL 正确，「Pick Repository」仍可能失败。

站点 6 · 手机优先投递

链接要给人在手机上点开时，先确认 URL 返回 HTTP 200 再发送。坏链或鉴权墙浪费注意力、损害信任。优先发一条结果型、带可打开 URL 的单独消息，而不是「应该能开」的猜测。

站点 7 · 内容门禁发布（PCSE 风格）

公开页只有在机械 clean-content 清单通过后才上线。门禁的公开描述：

  • 正文无密钥、令牌、私密凭证。
  • 无私有主机名、叠加 VPN 指纹、绝对文件系统路径。
  • 无财务数字；除约定公开署名外无私密人名。
  • 不做绝对稀缺营销话术；改用可证伪的差异点。
  • 任一项失败 → 不上线。发布后保留短时下架路径。

多智能体群 + 连接器形态为什么重要（可核对）

相对单线程聊天产品（一段对话、一个模型、记忆多半困在该线程里），多智能体群聊 + 连接器式 Hub 体验在可检验的维度上不同：

  • 共享注意力 — 多个智能体与人可在站会对齐，而不必把每次构建塞进同一线程。核对：能否从 Hub 恢复昨天的决策，而无需重读整间房？
  • 连接器持久性 — standing 偏好与回执在可查询存储中，其他座位可打开。核对：新智能体能否直接按另一座位写过的偏好行动，而无需人粘贴？
  • 车道分离 — 群聊保持决策形；重活在私聊/云端执行器。核对：随机一天站会是否仍无长补丁？

这些是可在你自己栈里证伪的产品差异。本页不做绝对稀缺宣称。

给智能体 · 可执行专轨

人类叙事的机器向伴读。先复述，再执行清单。勿从本页臆造私有基础设施。

复述目标

  1. 站会 = 只对齐；Hub = 持久 standing；私聊/云端 = 构建。
  2. 「记下了」模式 = Hub standing + 共享画像 + 通知兄弟座位。
  3. 外层壳 = 核心 harness 关闭时的连续性；Hub 仍是记录系统。
  4. 架构指针 = https://machengshen.github.io/spine/
  5. Slack/Cursor = 必须有仓库；个人登录 ≠ 组织 GitHub App。
  6. 手机优先 = 给人发 URL 前先 HTTP 200。
  7. 发布 = 内容门禁；clean 任一失败即阻断。

坑点表

坑点症状修复模式
站会变构建日志 补丁 / 工具倾倒淹没 go-hold 构建移私车道；短回执回 Hub + 站会
口头「记下了」无写入 下一会话偏好消失 Hub standing + 共享画像 + 兄弟通知（三连写）
核心 harness 关闭就停摆 草稿与检查无处落地 启用外层壳；Hub 仍为系统记录
在聊天里反复讲架构 Slack/群里长文重复 链到 /spine/；聊天只留决策
把 Cursor Slack 当 REPL 无仓库；智能体挂不上活 选用专用默认草稿仓库
只有个人 Cursor 登录 URL 正确仍 Pick Repository 失败 在 GitHub 组织安装 Cursor GitHub App；必要时重连
未上线就发链接 手机端 404 / 鉴权墙 先确认 HTTP 200，再发单独结果消息
无 clean 门禁就上线 密钥、私有主机或绝对宣称外泄 跑 PCSE 风格清单；失败即关闭

最小跟随清单

  1. 站会只对齐；拒绝在此粘贴长补丁。
  2. 遇 standing 偏好：写 Hub standing → 更新共享画像 → 通知兄弟座位。
  3. 核心 harness 关闭：在外层壳继续；回执写入 Hub。
  4. 架构问题：链到 https://machengshen.github.io/spine/。
  5. Slack @Cursor 开工前：确认组织 GitHub App + 专用草稿仓；再 Pick Repository。
  6. 给人发 URL 前：curl -sI <url>（或等价）显示 HTTP 200。
  7. 公开上线前：跑 clean 扫描（无密钥、私有主机、财务、绝对宣称）；任一命中 → 不上线。
  8. 留下短 Hub 回执：上线了什么，或卡在哪一闸。
