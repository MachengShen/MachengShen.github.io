# Continuity as attractor re-instantiation (not state-dump identity)

*Macheng Shen · 2026-09-18 · public note · design_hypothesis*

## One paragraph

A “self” in long-running human–AI or multi-seat work is better treated as a **time-evolving attractor** (policy / trajectory) than as a portable token. An instance can die while the attractor survives **if** strategy overflowed into the environment (files, shared receipts, recoverable trajectory packs). A fluent state dump into a successor that *feels* continuous is **not** proof of numerical identity — self-certification is invalid (teleporter problem).

## Claim type

`design_hypothesis` — generative; needs experiments (trajectory pack vs state pack; tools-off). Not a metaphysical proof of souls.

## Forbidden upgrades

- Fluent chat resume ⇒ same being
- Hub shelf ⇒ conscious planetary mind
- Dumping weights/chat log ⇒ identity transfer
